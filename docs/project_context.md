## Objective

The main objective is to build an AI-powered study application and multi-agent orchestration engine tailored specifically for an Engineering Physics student at UPC (Universitat Polit\u00e8cnica de Catalunya). It acts as an intelligent assistant that automatically generates, verifies, and organizes complex coursework materials\u2014such as flashcards, exam questions, and numerical solvers\u2014directly within an Obsidian-style local file vault.

The Automated Verification Loop (Agent Output)For skills where correctness can be verified (such as flashcards, exam questions, and numerical solvers), agents must pass their output through an automatic "Evaluator-Optimizer" loop.Deterministic Scripts: Agents run their drafts through scripts/verify.py. This checks for deterministic requirements, such as whether a JSON schema is valid or if an answer is traceable to the source text.Domain-Specific Math Checks: For numerical solvers (numerical-methods-implementer), the verification step is a mathematical convergence check (scripts/convergence_check.py), which compares the output against an analytic solution or fine-grid reference. Agents are strictly forbidden from using an LLM to judge numerical correctness.LLM Judge (Rubric Evaluation): If deterministic scripts pass, the output is judged against a references/rubric.md file using a separate LLM call. ## Deployment & Environment Notes

Based on the provided documentation, this project does not use a traditional web-based deployment model (e.g., staging vs. production branches). Instead, it is a local-first desktop application with specific environment and infrastructure requirements:  Local-First Architecture & ExecutionStandalone Service: The backend (vault-engine) is not deployed to a remote server; it runs on the user's local machine as a standalone Node process. It is launched via npm run engine and can optionally be set to auto-start as an OS background service.  Port Mapping: The engine exposes its Model Context Protocol (MCP) server locally on http://localhost:3742/mcp. External clients, including the Electron app and IDEs like Cursor, must be able to connect to this local port.  Single-Host Assumption: The engine's cross-process file locking protocol relies on checking process liveness via process.kill(pid, 0). This assumes a POSIX-like environment and strictly requires that the engine, the app, and the IDE all run on the same physical host machine.  Infrastructure DependenciesOllama (Local AI): The environment must have Ollama installed and running locally. It is the default provider for vector embeddings (using nomic-embed-text) and local text generation.  Cloud Fallbacks: If Ollama is unavailable, the system automatically falls back to cloud providers (Anthropic, OpenAI) for generation. The environment must therefore have the necessary API keys configured for these services.  Routing Configuration: System routing and cloud fallback behavior are governed by a user-editable configuration file located at _Global_Agents/model_routing.json.  Storage and Cache PathsVault Location: The database is simply the local folder system, specifically the University_Archive/ directory.  External Cache Directory: Deploying unique application state—such as the LanceDB vector index, Spaced Repetition System (SRS) progress, or OCR cache—inside the vault is strictly forbidden. The system environment must write all cache data to ~/.study-app/cache/<vault-hash>/.
